# Goal

为整个平台创建 Docker 容器化配置，支持本地开发、树莓派家庭部署和 VPS 部署，并配置 GitHub Actions 自动化构建。

# In Scope

- **新建**：`Dockerfile`（Next.js，多阶段构建，standalone 模式）
  - 阶段 1 (deps)：安装 pnpm 依赖
  - 阶段 2 (builder)：`pnpm build`
  - 阶段 3 (runner)：仅复制 `.next/standalone/`，最终镜像 < 500MB

- **新建**：`my-invest-global/Dockerfile`（Python FastAPI）
  - 基于 `python:3.13-slim`
  - `uv sync --frozen` 安装依赖
  - 暴露 8000 端口
  - 多阶段构建，避免 dev 依赖进入镜像

- **新建**：`docker-compose.yml`（根目录，管理两个服务）
  ```yaml
  services:
    nextjs:
      build: ./OpenStock
      ports: ["3000:3000"]
      env_file: ./OpenStock/.env
      depends_on: [python-api]
    
    python-api:
      build: ./my-invest-global
      ports: ["8000:8000"]
      env_file: ./my-invest-global/.env
      volumes:
        - ./my-invest-global/data:/app/data
      restart: unless-stopped
    
    neo4j:  # 可选
      image: neo4j:5-community
      profiles: ["with-neo4j"]
      ...
  ```

- **更新**：`next.config.ts` 添加 `output: 'standalone'`

- **新建**：`.github/workflows/ci.yml`
  - trigger: push to `main`
  - steps: pnpm install → typecheck → test → lint → build
  - （部署步骤可选，文档说明 SSH 方式）

- **新建**：`docs/deployment.md`
  - 本地开发启动步骤
  - 树莓派部署步骤（含 ARM64 注意事项）
  - Cloudflare Tunnel 配置步骤
  - VPS 部署步骤（含 Nginx + Let's Encrypt）

# Out of Scope

- 自动推送到 GitHub Container Registry（可手动操作）
- 多节点 K8s 部署

# Implementation Notes

树莓派 ARM64 注意事项：
- Docker 镜像指定 `platform: linux/arm64`
- Mac 上用 `docker buildx build --platform linux/arm64` 交叉编译
- Neo4j 树莓派内存限制：`NEO4J_HEAP_MAX_SIZE=512m`

# Acceptance Criteria

- `docker compose up --build` 在 Mac 上成功（约 3-5 分钟首次构建）
- `http://localhost:3000` 渲染 OpenStock 首页
- `http://localhost:3000/api/cn/health` 返回 `{"status": "ok"}`
- `docker images` 显示 nextjs 镜像 < 500MB，python-api 镜像 < 1.5GB
- `pnpm typecheck` 在 CI workflow 中通过
