# Goal

创建 AI 信号页，展示 LangGraph + Claude 生成的 A 股投资信号，并支持手动触发信号生成。

# In Scope

- **新建**：`app/(root)/cn/signals/page.tsx`
- **新建**：`components/cn/Signals.tsx`（从 Tab4Signals.tsx 移植）

  核心功能：
  - 宏观红绿灯 + 弹性仓位目标（MacroPanel）
  - 仓位偏差仪表盘（RebalanceGauge）
  - 「触发分析」按钮（调用 `useTriggerAnalysis()`）
  - 信号列表（每条：代码、名称、composite_score、action_code 色块、三维评分条）
  - 加载状态（LangGraph 运行中提示）

- **关键**：`useTriggerAnalysis()` 走 Next.js 代理层（`/api/cn/analysis/trigger`），采用**job-id 轮询**模式，避免 Vercel 10s 超时同时不绕过统一 Auth/JWT 设计

# Out of Scope

- KG 子图可视化
- 信号历史记录对比

# Implementation Notes

信号生成的两条路径（均经过 Next.js 代理，不直连 Python）：

```
普通查询（useLatestAnalysis）
  浏览器 → /api/cn/analysis/latest → Python FastAPI（<5s，单次请求）

触发新分析（useTriggerAnalysis）— job-id 轮询模式
  Step 1: 浏览器 → POST /api/cn/analysis/trigger → Python FastAPI
          Python 立即返回 { job_id: "xxx" }（<1s）
  Step 2: 浏览器每 5s 轮询 GET /api/cn/analysis/status/{job_id}
          Python 返回 { status: "running"|"done"|"error", result?: {...} }
  Step 3: status === "done" 时渲染信号列表
```

**为什么不直连 Python**：ADR-001 和 REQ-003 的设计是 Next.js 服务端持有 passphrase/JWT 并代理所有 `/api/cn/*` 请求。直连方案要么造成 401，要么须暴露 Python 端口和放松鉴权，破坏统一 Auth 设计。

**为什么不用 SSE**：Next.js Edge/Node 的 SSE 在 Vercel 上仍受 Streaming Response 时限约束，job-id 轮询更简单且无状态，易于调试。如后端已实现 SSE endpoint，也可替换为 `EventSource` 消费 `/api/cn/analysis/stream/{job_id}`，两者均符合本设计原则。

**Python 后端需同步支持**（PHASE-003 实施时确认）：
- `POST /api/analysis/trigger` → 异步启动 LangGraph，立即返回 `{ job_id }`
- `GET /api/analysis/status/{job_id}` → 返回运行状态和结果

# Acceptance Criteria

- 触发分析后 UI 显示加载状态（spinner / 进度条）
- 信号返回后按 composite_score 降序展示
- `action_code` 颜色编码（strong_add=绿, hold=蓝, reduce=橙, stop_loss=红）
- 网络超时（Python 后端未响应）时显示友好错误而非白屏
